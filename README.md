# 共享待看 · Shared Watchlist

和朋友共用的待看清单。粘链接进来，各自打勾，所有人都看完了就自动归档；每条底下能留想法，只有房间里的人看得到。

> **一句话**：个人项目，一个 PWA（渐进式网页应用）。纯静态前端 + Supabase（Postgres、Realtime、Edge Functions），和朋友在日常真实使用。
>
> **技术栈**：原生 JavaScript（无框架、无构建步骤）· Service Worker · Supabase Postgres / Realtime / Edge Functions（Deno）· Web Push（VAPID）· 数据库触发器 + `pg_net`
>
> **几个设计取舍**
> - **云端没配就直接报错，不偷偷退回本地模式**：分享类应用如果静默降级，你以为在用，朋友那边其实什么都看不到。
> - **「所有人都看完」才归档，而且归档只进不退**：新成员加入不会让旧条目复活，只有本人取消打勾才会撤回。
> - **没有注册登录，身份靠个人钥匙 + 找回码**：专门处理 iOS「添加到主屏幕」后存储与 Safari 隔离导致的身份分裂，提供合并功能。
> - **推送走数据库触发器，而不是控制台 Webhook**：少一层依赖；推送失败不影响写入。
> - **安全边界写在明处**：见文末「关于安全性」。

视频存在原平台（B站/小红书/抖音/YouTube…），这里只记 **链接 + 进度 + 评论**，不下载、不转存、不播放。

---

## 先说清楚它是什么

清单按**房间**分。一个房间一份清单，配一个或几个朋友；和不同的人分享不同的东西，就开不同的房间。房间靠链接邀请，没有注册登录。

数据全部在 Supabase 上，所以**必须先配好云端才能用**（下面 10 分钟搞定）。没配的话打开会直接报错——这是故意的：分享类应用如果偷偷退回本地模式，你以为在用，朋友那边其实什么都看不到。

## 配置（约 10 分钟）

### 1. 建 Supabase 项目
到 [supabase.com](https://supabase.com) 注册，新建一个项目（免费额度对这种规模绰绰有余）。

### 2. 建表
控制台左侧 **SQL Editor** → 新建查询 → 把 `supabase-schema.sql` 整个文件粘进去 → Run。

脚本开头会 `drop` 旧表再重建，所以**重跑一次是安全的**，代价是清空已有数据。

然后依次跑 `supabase-migration-2.sql`（个人钥匙）和 `supabase-migration-3.sql`（推送订阅表）。这两个都是纯追加的，不会动数据，重跑也安全。

### 3. 填钥匙
把 `config.example.js` 复制一份，命名为 `config.js`（已在 `.gitignore` 里，不会被提交）。
控制台 **Settings → API**，复制 Project URL 和 publishable（anon）key，填进 `config.js`：

```js
window.WL.config = {
  url: 'https://YOUR-PROJECT.supabase.co',
  anonKey: 'YOUR_SUPABASE_PUBLISHABLE_KEY',
  vapidPublicKey: 'YOUR_VAPID_PUBLIC_KEY'
};
```

`supabase-migration-4.sql` 里也有同样两个占位符，运行前一起换掉。

刷新页面，能进到房间列表就说明连上了。

### 4. 部署上线
需要一个公网地址，两个人才能同时访问。最省事的是 [Netlify Drop](https://app.netlify.com/drop)：把整个项目文件夹拖进网页（记得先建好 `config.js`），几秒后拿到一个网址，完事。（Vercel、GitHub Pages、Cloudflare Pages 同理，纯静态文件，没有构建步骤。）

### 5. 加到主屏幕
两人各自用手机浏览器打开那个网址：

- **iPhone**：Safari → 分享 → 添加到主屏幕
- **Android**：Chrome → 菜单 → 安装应用 / 添加到主屏幕

之后就是个图标，点开即用，跟 App 没区别。

朋友点你发的邀请链接进来时，会让他设名字和头像——可以选 emoji、上传照片，或者留空用首字母。上传的照片会在浏览器里裁成 160×160 的 JPEG（约 10KB）再存进数据库，不需要额外配图床。

## 主页

不带 `?r=` 打开应用就是主页，列出你所在的全部房间。每张卡片显示成员头像、待看条数，以及**「N 条等你」**——就是别人都看过、只差你的那些。等你的房间排在最前面。

这个主页对每个人都成立：你朋友打开他自己的应用，看到的是他自己那些房间。

### 换手机 / 加到主屏幕 / 数据被清了

主页底部的**「复制我的找回码」**给你一条专属链接，存到备忘录里。在新设备上直接打开它就能恢复所有房间和身份。

**iOS 加到主屏幕的人一定会遇到这一步**：iOS 给主屏幕应用配的是一套独立存储，跟 Safari 不共享，所以图标点开是空的——而且它没有地址栏，你没法把找回链接输进去。解决办法是主页上的**「我要找回房间」**：把找回码粘进去（整条链接或者只有那一串码都认），房间就都回来了。每台设备、每个主屏幕图标只需要做一次。

原理是每个人有一把随机生成的个人钥匙，你在各个房间的成员记录都挂着这把钥匙。**这条链接等于你的身份**——谁拿到谁就能进你所有的房间，所以别发到公开的地方。

（老成员没有钥匙也不要紧：在那台设备上打开一次主页，钥匙就自动补上了。）

### 身份分裂了怎么办

**每套存储空间会各自生成一把钥匙**——电脑 Safari 一把、手机 Safari 一把、主屏幕应用又一把。所以很容易出现「A 房间挂在钥匙 1 名下、B 房间挂在钥匙 2 名下」，任何一条找回码都只能找回一半。

解决办法：在其中一台设备上粘另一把钥匙的找回码，应用会问要不要**合并**。确认后两边的房间归到同一把钥匙，之后一条找回码就能全拿到。

判断方法很简单：如果找回后房间少了，就是分裂了——去缺失的那个房间所在的设备上复制它的找回码，回来粘一次并合并。

## 提醒（推送）

**只有 iPhone 能用，而且必须是「添加到主屏幕」的那个图标。** Safari 标签页里 iOS 根本不提供推送接口。安卓在国内也用不了——Chrome 的网页推送底层走 Google FCM，被墙。

开启方式：主屏幕应用 → 主页最底下 → 「开启提醒」。

### 已经全自动

```
朋友加视频 / 留言
      ↓  数据库触发器（migration-4）
   Edge Function「notify」
      ↓  苹果推送 APNs
    你的 iPhone
```

| 发生什么 | 谁收到 | 内容 |
|---|---|---|
| 有人加视频 | 房间里其他所有人 | 「XX加了新视频」 |
| 有人留言 | 房间里其他所有人 | 「XX在《某视频》下说」 |
| 有人看完了你分享的 | **只有分享者** | 「XX看完了你分享的」 |

第三条是「我推给你的那个你看了没」——分享者真正关心的事。
单纯「某某打了个勾」不推给别人，那对旁人没有意义。

几条已生效的规则：

- **只推给别人**，自己的动作不推给自己
- **按话题折叠**：同一条视频下的评论共用一个 tag，通知中心里只占一条，不刷屏
- **失效订阅自动清理**：推送返回 404/410 就把那条订阅删掉
- **推送失败不连累主功能**：触发器里包了异常处理，推送服务宕机也不影响「加视频」

### 为什么不用控制台的 Database Webhooks

试过，报错 `schema "supabase_functions" does not exist` —— 那个功能依赖一个没初始化的内部 schema。
`supabase-migration-4.sql` 自己建触发器，效果完全一样，还少一层依赖。

触发器里用的是 **anon key** 而不是 service_role：Edge Function 只要求一个合法 JWT，
而 anon key 本来就是公开的，没必要把万能钥匙写进数据库函数。

### 推送需要的密钥

1. 生成一对 VAPID 密钥（例如 `npx web-push generate-vapid-keys`）。
2. **公钥**填进 `config.js` 的 `vapidPublicKey`。
3. **私钥**只放在 Supabase 控制台 → Edge Functions → Secrets，变量名 `VAPID_JWK`（JWK 格式），另外设置 `VAPID_SUBJECT`（`mailto:` 联系地址）和 `SITE_URL`。
4. 私钥**绝不能**进仓库或任何前端文件。

**换 VAPID 密钥的话所有人都要重新订阅一次**，别随便换。

### 改推送文案或规则

改 `supabase/functions/notify/index.ts`，然后到 Supabase 控制台
Edge Functions → notify → 编辑器里重新粘贴 → Deploy。

## 房间怎么用

清单是按**房间**分的。一个房间一份清单，配一个或几个朋友；和不同的人分享不同的东西，就开不同的房间。

**建房间**：打开应用（网址不带 `?r=`），输入房间名，比如「和小林」。

**拉人进来**：进房间后点右上角**邀请**，链接就复制好了，发微信给朋友。他点开就能加入，设自己的名字和头像。

**切房间**：点右上角**切换房间**，会列出这台设备上你待过的所有房间。

**人数不限**：两个人、三个人、五个人都行。只有当**所有成员**都打勾之后，这条才算完成。

日常流程：

1. 在 B站/小红书 里点「分享 → 复制链接」
2. 打开对应的房间，把剪贴板整段粘到输入框

   标题会自动认出来（分享文本里的 `【标题】` 就是），认不出来的手写一句
3. 点「加入清单」，房间里其他人实时就能看到
4. 看完了勾「我看了」；右边那排小头像显示别人看没看，灰的是还没看
5. 所有人都勾完，这条自动进「已完成」并划掉
6. 想说什么就在这条底下留言，跟便签一样

### 成员管理

点顶部那排小头像（写着「N 人 ›」）打开成员列表。每个人下面会显示他的活动记录——加了几条、打了几个勾、发了几条评论——**零记录的基本就是重复加入产生的幽灵**，可以放心移除。

移除一个人之后，那些「剩下的人其实都看过了」的条目会立刻补算成已完成。

自己那一行的按钮是「退出」，退出后这台设备会忘掉这个房间；想回来重新打开邀请链接即可。

### 身份是怎么记住的

三层保险，从好到差：

1. **个人钥匙**（服务端）—— 主页那条找回链接。换设备、清数据都能一次恢复全部房间和身份。
2. **本机记录**（localStorage）—— 日常走这条，最快。但 **iOS Safari 七天不访问会清掉它**。
3. **手动认领** —— 前两条都断了、但手上还有房间链接时，打开会列出现有成员让你认领自己。

第 3 条存在的意义是防止重复加入：直接新建一个人的话，房间里会堆出幽灵成员，「所有人都看过」就永远凑不齐了。

### 几个规则说明

- **一个人的时候不会归档**。房间里只有你自己时，勾了也不算完成——否则加一条勾一下就消失了。等朋友加进来才开始算。
- **归档只进不退**。「勾上」这个动作只可能让一条完成，绝不会让已完成的退回；只有**本人取消打勾**才会把它撤回待看。所以新人加入房间不会让一堆旧条目复活。
- **同一个人在不同房间可以用不同名字头像**。房间之间是独立的。

## 关于安全性，说清楚

`anon key` 会明文出现在前端代码里——这是 Supabase 前端应用的常规做法。**房间的门禁就是那个 8 位短码本身**：拿到某个房间链接的人就能进那个房间读写。

具体边界：

- 朋友 A 拿到的是 A 房间的链接，他**看不到** B 房间的内容，也收不到 B 房间的实时推送（订阅按 `room_id` 过滤过）。
- 但这是「不知道就进不去」，不是「不让进」。懂技术的人拿着 anon key 直接调 API 是能查到所有房间的。
- 结论：朋友之间分享视频链接完全够用，别放任何敏感内容。

想更严的话，后续可以加 Supabase 匿名登录 + 按成员身份收紧 RLS 策略。

## 文件说明

| 文件 | 干什么的 |
|---|---|
| `index.html` | 页面结构 |
| `app.js` | 界面逻辑：渲染、打勾、评论、身份 |
| `store.js` | 数据层。房间、成员、条目、打勾、评论，全部走 Supabase |
| `parse.js` | 从分享文本里抠出链接、平台和标题 |
| `app.css` | 样式，跟随系统深浅色 |
| `sw.js` | Service Worker。**改完前端代码记得把里面的 `VERSION` 改一下**，否则老用户可能一直跑旧代码 |
| `supabase-schema.sql` | 建表脚本。开头会清掉旧表，重跑安全但会清数据 |
| `supabase-migration-2.sql` | 追加个人钥匙那一列，跑在建表脚本之后 |
| `supabase-migration-3.sql` | 追加推送订阅表 |
| `supabase-migration-4.sql` | 建触发器，加视频/留言时调推送函数 |
| `supabase-migration-5.sql` | 打勾也走触发器（函数内部只在该通知分享者时才发） |
| `config.example.js` | 配置模板。复制为 `config.js` 再填 Supabase 的 url 和 key |
| `supabase/functions/notify/index.ts` | 推送用的 Edge Function 源码 |

### 想再加平台？

`parse.js` 顶上的 `PLATFORMS` 数组加一行就行，域名匹配上就会显示对应的彩色小标签：

```js
{ id: 'twitter', name: 'X', hosts: ['x.com', 'twitter.com'], color: '#000000' }
```

不在列表里的链接也能正常添加，只是标签显示成灰色的「链接」。
